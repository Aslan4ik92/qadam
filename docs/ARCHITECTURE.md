# Архитектура QIDIR

```text
┌──────────────────────────────────────────────────────────────────────┐
│  apps/desktop  (Tauri 2)                                             │
│  ┌──────────────────────────┐   invoke / events   ┌───────────────┐  │
│  │ Svelte 5 + TypeScript UI │ ◄─────────────────► │ Rust commands │  │
│  └──────────────────────────┘                     └───────┬───────┘  │
└───────────────────────────────────────────────────────────┼──────────┘
                                                            │ Arc<Engine>
┌───────────────────────────────────────────────────────────▼──────────┐
│  crates/qidir-core                                                   │
│                                                                      │
│   engine ── settings, lifecycle, watcher, progress, preview          │
│     ├─ index    crawler → extract workers → IndexWriter (tantivy)    │
│     │           manifest (redb): path → (mtime, size)                │
│     ├─ search   query parser → tantivy queries, facets, snippets     │
│     ├─ extract  docx/doc/xlsx/pptx/odf/pdf/rtf/html/epub/fb2/text    │
│     └─ analysis tokenizer → lowercase → stems → folding (RU/KZ/EN)   │
└──────────────────────────────────────────────────────────────────────┘

          │ тот же Engine
┌─────────┴──────────┐
│ crates/qidir-cli   │  qidir index / search / preview / extract / analyze
└────────────────────┘
```

## Слои

### `qidir-core` — ядро

Библиотека без зависимостей от UI. Используется и приложением, и консольной утилитой, полностью тестируется на любой ОС.

#### `analysis` — многоязычный анализ текста

Одна и та же цепочка применяется при индексировании и к запросу:

1. **Токенизация.** Токен — максимальная последовательность буквенно-цифровых символов Unicode. Знаки препинания, пробелы и `_` — разделители. Токены длиннее 64 символов (хэши, base64) отбрасываются.
2. **Нижний регистр.**
3. **Определение языка токена** по письменности: латиница → английский; кириллица с буквами `ә ғ қ ң ө ұ ү һ і` → казахский; остальная кириллица → «русский или казахский без специфических букв»; цифры/смешанные → без стемминга.
4. **Стемминг** (только в режиме *Smart*). На одной позиции индексируется несколько вариантов терма:
   - точная свёрнутая форма — всегда (точные совпадения ранжируются выше, а запрос с русской раскладки находит казахские слова);
   - стем языка: Snowball Russian / Snowball English / стеммер казахских суффиксов;
   - для кириллических токенов без казахских букв — **оба** стема, русский и казахский. Такие слова неразличимы (`мектеп`, `бала`, `дала` — казахские слова, записанные только русскими буквами), а документы в Казахстане часто двуязычны. Симметричное применение обоих стеммеров даёт корректную морфологию для обоих языков ценой ~30 % роста постингов для кириллицы.
5. **Свёртка символов:** `ё→е`, казахские буквы → ближайшие русские, украинские/белорусские → русские, латиница без диакритики. Буква `й` не раскладывается.

Казахский стеммер (`analysis/kazakh.rs`) снимает суффиксы «снаружи внутрь» по реальной морфотактике: личные окончания → падеж → принадлежность → множественное число → глагольные/словообразовательные (последние — только если ничего другого не снято). Стем не короче трёх букв, не более четырёх снятий. Стеммер намеренно консервативен и симметричен: даже неидеальный стем даёт правильные совпадения, потому что запрос обрабатывается точно так же.

Поле `content` индексируется анализатором `qidir_stem`, поле `content_exact` — анализатором `qidir_exact` (без стемминга). Режим поиска выбирает поле.

#### `extract` — извлечение текста

| Формат | Способ |
|---|---|
| `txt md csv log json yaml ini …`, исходный код | Определение кодировки: BOM → UTF-16 без BOM (по старшим байтам кодовых единиц, включая кириллицу U+04xx) → валидный UTF-8 → `chardetng` (cp1251, KOI8-R/U, CP866, …). Бинарные файлы с расширением текста отбрасываются. |
| `docx docm dotx` | ZIP → `word/document.xml` + колонтитулы, сноски, примечания (quick-xml, потоково). Удалённый текст и коды полей пропускаются. |
| `pptx pptm ppsx` | Слайды в порядке номеров, затем заметки. |
| `xlsx xlsm xlsb xls ods` | `calamine`: все листы, значения ячеек, даты Excel в ISO. Лимит 2 млн ячеек. |
| `odt odp fodt fodp` | `content.xml` или плоский XML. |
| `doc dot` (Word 6/95/97–2003) | OLE2 (`cfb`): FIB → таблица кусков (piece table) в `0Table/1Table`, куски UTF-16LE и «сжатые» 8-битные; для Word 6/95 — диапазон `fcMin..fcMac` с определением кодировки. Управляющие символы Word и коды полей вычищаются. |
| `pdf` | `pdf-extract` внутри `catch_unwind`: сломанный PDF никогда не останавливает индексатор. |
| `rtf` | Собственный парсер: группы, управляющие слова, `\'hh` в кодовой странице `\ansicpgN` (1251 для русских RTF), `\uN` с `\ucN`, пропуск `fonttbl`, `pict`, `info` и др. |
| `html htm xhtml mht` | Толерантный к ошибкам стриппер тегов: `script/style` вырезаются, блочные теги → переводы строк, сущности декодируются. |
| `epub` | Главы в порядке `spine` из OPF. |
| `fb2 xml svg …` | Текст XML с сохранением абзацев; `binary` пропускается. |
| остальные | Индексируются по имени. |

Все экстракторы возвращают ошибку вместо паники; файл с ошибкой индексируется по имени и попадает в счётчик «не удалось».

#### `index` — индекс

Схема tantivy (`index/schema.rs`):

| Поле | Тип | Назначение |
|---|---|---|
| `path` | STRING, stored | идентификатор документа (удаление/обновление по терму) |
| `path_text` | TEXT exact | поиск по словам в пути (`path:`) |
| `name` | TEXT exact, stored | имя файла (`name:`, буст ×3 в общем поиске) |
| `ext`, `category`, `root` | STRING fast | фильтры и фасеты |
| `size` u64, `modified` i64 | fast | фильтры диапазонов и сортировка |
| `has_content` u64 | fast | «только файлы с текстом» |
| `content` | TEXT stem | полнотекстовый поиск в умном режиме |
| `content_exact` | TEXT exact | точный режим, префиксы, маски, нечёткий поиск |
| `body` | stored | текст для сниппетов и предпросмотра (сжат в doc store; можно отключить) |
| `encoding` | STRING stored | кодировка исходного файла |

**Индексатор** (`index/indexer.rs`): обход `walkdir` с фильтрацией glob-исключений и скрытых файлов на уровне поддеревьев → канал → N потоков извлечения (по умолчанию `ядра−1`) пишут документы в общий `IndexWriter` (под `RwLock`: добавление — read-lock, коммит — write-lock) → отпечатки `(mtime, size)` пакетами в `redb`-манифест. После обхода пути из манифеста, не встреченные в этом проходе или не входящие в активные корни, удаляются из индекса. Отмена проверяется в обходе и воркерах; при отмене всё сделанное коммитится. Прогресс — атомарные счётчики, снимок каждые 250 мс.

**Наблюдатель** (`index/watcher.rs`): `notify` + дебаунс 1,5 с; изменённые пути обрабатываются `Engine::update_paths` (файл → переиндексация при изменении отпечатка; удаление папки → удаление по префиксу из манифеста). Полная индексация и инкрементальные обновления сериализуются одним мьютексом.

#### `search` — поиск

`search/query.rs` — разбор запроса в конъюнкцию групп-дизъюнкций плюс исключения. Каждое слово ищется в `content(_exact)` и `name` (с бустом). Термы одной позиции (стем + точная форма) объединяются `Should`; фразы разворачиваются в декартово произведение вариантов позиций (до 64 фраз), при превышении — фразы из основных стемов и из точных форм. Префиксы/маски → `RegexQuery` по точному полю, нечёткие → `FuzzyTermQuery`. Фильтры — `TermQuery`/`RangeQuery` по fast-полям.

`search/mod.rs` — выполнение: `Count` + `TopDocs` (по релевантности или `order_by_fast_field`) + собственный коллектор фасетов по строковым fast-полям (`ext`, `category`, `root`). Сортировка по имени — в памяти по окну из 5000 лучших результатов.

`search/highlight.rs` — сниппеты и подсветка тем же анализатором, что и индекс: подсвечиваются именно те словоформы, которые сматчились. Большие тексты сканируются кусками по 64 КБ до первого совпадения, поэтому сниппет многомегабайтного файла стоит микросекунды.

#### `engine` — фасад

`Engine` — потокобезопасный объект (`Arc<Engine>`): открытие/миграция индекса (несовместимая схема → пересборка), настройки, запуск/отмена индексации в фоне, прогресс, наблюдение, поиск, предпросмотр (из сохранённого `body` или повторным извлечением с диска), статистика.

### `qidir-cli`

Тонкая обёртка над `Engine` (`clap`). Используется в CI как сквозной тест и удобна для скриптов.

### `apps/desktop`

- `src-tauri` — бэкенд: владеет `Engine`, команды (`commands.rs`) с сериализацией через `serde`, поток-тикер раз в 250 мс шлёт события `index-progress`/`index-finished`, плагины `dialog`, `opener`, `clipboard-manager`, `window-state`, `single-instance`. Логи — `%LOCALAPPDATA%\QIDIR\logs`.
- `src` — Svelte 5 (runes) + TypeScript. Слой `lib/api` типизирует контракт команд и при запуске в обычном браузере подменяется мок-бэкендом — так интерфейс разрабатывается и снимается скриншотами без Windows. Локализация `lib/i18n` (ru/kk/en), состояние в `lib/stores`, виртуализированный список результатов, панель предпросмотра, диалог настроек.

## Данные на диске

```text
%LOCALAPPDATA%\QIDIR\
  settings.json      настройки (JSON, атомарная запись)
  manifest.redb      отпечатки файлов и метаданные индекса
  index\             сегменты tantivy
  logs\              qidir.log.YYYY-MM-DD
```

## Производительность

- Индексирование ограничено извлечением текста; оно параллельно и не блокирует поиск (поиск идёт по последнему коммиту).
- Поиск — миллисекунды на сотнях тысяч документов: инвертированный индекс с fast-полями для фильтров и сортировок.
- Сниппеты не требуют повторного чтения файлов (текст хранится сжатым в doc store); при отключённом хранении предпросмотр извлекает файл заново.

## Ограничения и планы

- Сканированные PDF без текстового слоя не индексируются (OCR не входит).
- Старые бинарные `.ppt`/`.xls` через `calamine` (xls) поддерживаются, `.ppt` — по имени.
- Казахская латиница (алфавит 2021 г.) не транслитерируется в кириллицу.
- Сортировка по имени ограничена окном 5000 лучших результатов.
