# Участие в разработке

Спасибо за интерес к QIDIR! Коротко о правилах.

## Перед отправкой изменений

```bash
cargo fmt --all
cargo clippy -p qidir-core -p qidir-cli --all-targets -- -D warnings
cargo test --workspace --exclude qidir-desktop
cd apps/desktop && npm run check && npm run test && npm run build
```

CI выполняет то же самое плюс сборку установщиков на Windows.

## Принципы

- **Ядро не знает об интерфейсе.** Всё, что можно протестировать без окна, живёт в `qidir-core` и покрыто тестами.
- **Анализатор симметричен.** Любое изменение токенизации/стемминга/свёртки применяется и к индексу, и к запросу — меняйте `analysis` и при необходимости увеличивайте `SCHEMA_VERSION` (индекс пересоберётся у пользователей автоматически).
- **Экстракторы не паникуют.** Ошибка чтения файла — это `Err`, а не остановка индексатора. Добавляя формат, добавьте тест с синтетическим файлом (см. `extract/*/tests`).
- **Контракт UI ↔ бэкенд** описан в `apps/desktop/src/lib/api/types.ts` и должен совпадать с `serde`-структурами в Rust (camelCase). Мок-бэкенд в `mock.ts` обновляйте вместе с контрактом.
- **Локализация.** Каждая строка интерфейса проходит через `t()`, ключи должны присутствовать во всех трёх словарях (`ru`, `kk`, `en`) — это проверяет тест.

## Сообщения об ошибках

Приложите версию QIDIR, шаг воспроизведения, при проблемах с конкретным файлом — вывод `qidir extract <файл>` (без конфиденциального содержимого) и фрагмент лога из `%LOCALAPPDATA%\QIDIR\logs`.
